TODO 2: Why is the bounds check (if (i < n)) needed?
19532 blocks x 512 threads = 10,000,384 threads, but the arrays only have 10,000,000 elements. Without the check, the last 384 threads would read and write past the end of the arrays. That is undefined behaviour: the program may still print correct-looking results, or it may crash later.

Why round the number of blocks UP?
N / 512 in integer arithmetic gives 19531 blocks, which leaves the last 128 elements unprocessed. So I used (N + THREADS_PER_BLOCK - 1) / THREADS_PER_BLOCK = 19532.

THINK: Why is it a good idea to use a multiple of 32 for the threads per block?
The GPU executes threads in warps of 32. If the block size is a multiple of 32, every warp is full. If not, the last warp in each block runs partly empty and wastes lanes.

THINK: What happens to the total number of threads if I use 500 instead of 512?
Blocks needed = 10,000,000 / 500 = 20,000 exactly, so the total is exactly 10,000,000 threads and none are idle, unlike 10,000,384 with 512. However, 500 = 15 full warps + 20 threads, so the 16th warp of every block has only 20 of its 32 lanes active. The thread count is neater, but the warp usage is worse.
